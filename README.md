## 1. רקע, בחירת הבעיה ומה האג'נט עושה (הסבר קצר)

### הבעיה שנבחרה ולמה בחרתי בה
אחת הבעיות היומיומיות השוחקות ביותר בכל ארגון היא **תיאום פגישות מרובות משתתפים תחת אילוצים משתנים**. כשמנסים לתאם פגישה בין מספר עובדים (ולעיתים גם להתחשב באילוצים חיצוניים כמו תחזית מזג אוויר לפגישת חוץ/סיור), נוצר פינג-פונג ארוך של בדיקת יומנים, זיהוי התנגשויות, חיפוש חלופות ווידוא מול המשתתפים. בחרתי בבעיה זו מכיוון שהיא ממחישה באופן מובהק את ההבדל בין תוכנית רגילה לבין **Agent אוטונומי**: הפתרון אינו שליפת תשובה בודדת, אלא תהליך רב-שלבי של איסוף מידע, הסקת מסקנות, הפעלת כלים ואינטראקציה עם המשתמש.

### כיצד האג'נט פותר את הבעיה (מרכיבי האג'נט)
1. **קבלת מטרה (Goal):** האג'נט מקבל מטרה בשפה טבעית (למשל: *"תאם פגישת סיור בחוץ עם דני ויוסי השבוע"* או *"קבע פגישה עם דני בראשון ב-10:00"*).
2. **מוח וקבלת החלטות (LLM Reasoning Brain):** האג'נט מבוסס על `gpt-4o-mini` של OpenAI (באמצעות Function Calling). הוא מנתח את המטרה, מזהה מי המשתתפים ומהם האילוצים, ומחליט בעצמו אילו כלים להפעיל ובאיזה סדר. *(למערכת קיים גם מנגנון גיבוי מקומי - Fallback - למקרה שהקוד מורץ בסביבה ללא מפתח OpenAI).*
3. **שימוש בכלים (Tools) ובחינת התוצאה (Observation):**
   - `list_users`: שליפת רשימת העובדים ותפקידיהם.
   - `get_user_calendar`: בדיקת לוח הזמנים של עובד ביום נתון (`Sunday`, `Monday`, `Tuesday`).
   - `get_weather_forecast`: בדיקת תחזית מזג אוויר (נתוני הדגמה) כאשר מדובר בפגישת חוץ/סיור.
   - `schedule_meeting`: הצעת מועד פנוי (כולל נימוק מפורש בפרמטר `reason`) ושיבוץ ביומנים לאחר אימות זמינות (Dry-Run Validation) ואישור המשתמש (**Human-in-the-Loop**). אם המשתמש דוחה את ההצעה, האג'נט שומר את המועד שנדחה ומחשב מסלול מחדש.
4. **הפרדת סמכויות ותנאי סיום (Stopping Condition):** האג'נט עוסק **אך ורק בשיבוץ פגישות במשבצות פנויות** ואינו מוחק או מזיז פגישות קיימות על דעת עצמו. כאשר האג'נט סורק את כל הימים ומגלה שאין אף משבצת פנויה משותפת (כמו בתרחיש מול סמנכ"ל עמוס), הוא עוצר, מסביר למשתמש אילו פגישות חוסמות את התיאום, ומנחה את המשתמש לפנות/למחוק בעצמו משבצת ביומן אם הפגישה קריטית ואז לבקש שיבוץ מחדש.

## 2. הדגמה ופלט ריצה (מתוך הרצת האג'נט)

### תרחיש 1: פתרון התנגשות ביומן + אישור משתמש (Human-in-the-Loop)
```text
=================================================================
משתמש מחובר: עמית
מטרה שהתקבלה: אני רוצה לקבוע פגישת עבודה עם דני ביום Sunday בשעה 10:00 בנושא תכנון מערכת. אם תפוס, תמצא לנו שעה אחרת שפנויה לשנינו.
מצב מוח פעיל: OpenAI LLM (gpt-4o-mini)
=================================================================
-> 🔍 צעד #1: הפעלת כלי - בדיקת יומן עובד (get_user_calendar) [עמית, Sunday]
-> 🔍 צעד #1: הפעלת כלי - בדיקת יומן עובד (get_user_calendar) [דני, Sunday]

*******************************************************
[בקשת אישור מהמשתמש לפני שינוי ביומן]
  נושא: תכנון מערכת
  יום ושעה: Sunday בשעה 14:00
  משתתפים: עמית, דני
  נימוק האג'נט: ⏰ בשעה המבוקשת (10:00) יש התנגשות (דני תפוס ב-'כתיבת קוד') | ביום Sunday בשעה 14:00 שניכם פנויים.
האם לאשר את קביעת הפגישה? (כתבי 'כן' לאישור מפורש, או 'לא' / סיבת דחייה): כן
*******************************************************

-> ✅ המשתמש אישר! הפגישה שובצה ביומנים של כל המשתתפים
תשובת האג'נט הסופית:
הפגישה בנושא "תכנון מערכת" עם דני נקבעה בהצלחה ליום ראשון (Sunday) בשעה 14:00 ושובצה ביומנים של שניכם.
```

### תרחיש 3: הפעלת תנאי עצירה כשאין מועד פנוי משותף
```text

-> 🔍 בדיקת יומני עמית ואלון בימים Sunday, Monday, Tuesday
תשובת האג'נט הסופית:
🛑 אני מצטער, אך לא נמצא אף מועד פנוי משותף לשיבוץ עבור (עמית, אלון).
בדקתי את כל ימי העבודה במערכת (Sunday, Monday, Tuesday) ואין אף שעה שבה כל המשתתפים פנויים בו-זמנית.

💡 איך מתקדמים? (האג'נט אינו מוחק פגישות קיימות בעצמו):
• ביום Sunday בשעה 13:00 שאר המשתתפים פנויים, אך אצלך ביומן רשום 'אפיון מערכת'.
אם הפגישה קריטית לך, תוכלי למחוק/לפנות בעצמך את המשבצת הזו בטבלת היומן משמאל (לחיצה על 🗑️ ליד המשימה בלוח), ואז ללחוץ שוב על 'הפעל אג'נט' כדי שאשבץ עבורכם את הפגישה!
```
